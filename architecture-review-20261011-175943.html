Problem. One add is decided in five modules, joined by bookkeeping flags (url_asked, asked, Decided.ref_settled, Packages::Now/Later) that leak across the seams. The same decision is also made twice: --no-sync and sync paths call prepare_add with different modes. Bugs hide in how the pieces are called, not in the pure ones.

Solution. One Add module owns the sequence: expand, pin, ask, edit, sync, infer. Its interface is the repo as typed, the Prompter, Registry and Source, and a result that the CLI prints.

  • locality: ordering and the "was anything asked" rule live in one place
  • leverage: tests drive one interface with a scripted Prompter
  • cli.rs sheds ~250 lines of add orchestration
  • interface shrinks; the flag threading becomes internal
  • pin, tag_for, used stay pure behind it
ADR 0008 and 0009 describe this pipeline; this keeps their decisions and moves where they are implemented. No conflict.

Problem. The two stages are pure and well tested (ADR 0006); the shell that sequences them is copied across four entries, so the same rules are restated and each new exit needs a hint and a drift call.

Solution. Make the sequence one module whose entries differ only in whether an edit comes first and whether the run is a check.

  • locality: Hint and ordering rules in one body
  • delete one duplicated missing-Lock branch
  • leverage: lock, sync, edit share one interface
ADR 0006 says sync sets the Hint where it knows why a run stopped. This keeps that and only gathers where.

Tag listing is one seam with its own adapters; Source returns to cache and checkout only; "cannot list" is not a second adapter.

Problem. Source::tags shares a trait with checkout mechanics it has nothing to do with (the ADR says so), and Tags re-wraps it so --no-sync can answer "none". The only reason for NoTags is one flag.

Solution. Give tag listing its own seam, or let the caller say "no listing" directly, and drop the blanket impl.

  • Source interface shrinks by a method
  • delete the blanket impl and NoTags
  • contract tests for Source stop covering listing
ADR 0006 lists tags among Source's seven methods; this contradicts it. Worth reopening only if candidate 1 lands and Tags is still awkward.
